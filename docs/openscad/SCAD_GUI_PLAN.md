# OpenSCAD GUI 建模设计与状态

## 背景

OpenHarness 拥有一个 OpenSCAD 工作区，支持 Monaco 编辑器、多文件工作区持久化、OpenSCAD WASM 渲染、捆绑库索引和 Three.js 预览。GUI 建模工作在 `.scad` 文件之上添加了一个可视化编辑层，同时保持 OpenSCAD 源代码作为持久的真相来源。

GUI 并非旨在取代 OpenSCAD。以代码为先的用户可以继续直接编写 OpenSCAD，而以 GUI 为先的用户可以创建图元、插入模块实例、选择对象并应用变换，而无需手动编辑每个包装器。

## 产品原则

1. OpenSCAD 源代码保持为真相来源。
2. GUI 可编辑的对象必须具有稳定的源代码锚点。
3. GUI 支持应该是明确且可靠的，而不是假装覆盖完整的 OpenSCAD 语言。
4. 不支持的代码应尽可能保留，并通过 OpenSCAD WASM 进行渲染。
5. 自定义模块应可作为一等工件使用，即使其内部未在 JavaScript 中解释。

## 当前用户体验

GUI 控件位于 3D 预览区域内，而不是覆盖代码编辑器。

预览头部包含分组的工具栏：

- 创建：立方体、圆柱体、球体。
- 工件：从当前文件、工作区文件和引用的 OpenSCAD 文件中发现的模块。
- 操作：并集、差集、交集模板。
- 变换：平移、旋转、缩放。
- 轴向：自由、X、Y、Z。

3D 预览左侧包含一个可选择对象栏。每个 GUI 可编辑对象都从其 `@cad:id` 锚点列出。变换工具仅作用于选定的对象；否则普通视口鼠标操作继续控制相机。

代码编辑器工具栏包含一个自动渲染切换开关。启用后，代码更改会在短暂防抖后进行渲染，同时保持当前相机位置。手动渲染仍可通过渲染按钮使用。

## 源代码锚点

GUI 创建和 GUI 可编辑的代码块使用轻量级注释：

```openscad
// @cad:id=mg996r_with_horn_mqkehysv_2ioa9 type=module source=MG996R.scad
translate([0, 0, 0])
rotate([0, 0, 0])
scale([1, 1, 1])
mg996r_with_horn(type=0);
```

GUI 也识别旧的 `@oh:id` 锚点以兼容，但新代码应使用 `@cad:id`。

锚点元数据当前包括：

- `id`：唯一的 GUI 对象 ID。
- `type`：图元、布尔运算、变换或模块。
- `source`：模块源文件，或 `current` 表示来自活动文件的模块。

ID 通过类型/模块前缀加随机后缀生成。它们旨在在活动工作区内唯一，且足够稳定以支持源代码回写。

## 当前可编辑子集

当前 GUI 实现支持：

- 图元：`cube`、`sphere`、`cylinder`。
- 变换包装器：`translate`、`rotate`、`scale`。
- 布尔模板：`union`、`difference`、`intersection`。
- 来自当前/工作区/引用文件的模块实例。
- 需要时为模块源插入 `use <...>`。

浏览器端解析器有意保持有限。它可以直接预览简单的图元树，但自定义模块和复杂的 OpenSCAD 构造通过 OpenSCAD WASM 渲染。

## 模块发现与插入

模块选择器基于现有的 OpenCAD 符号索引构建。它扫描：

- 当前文件。
- 其他工作区文件。
- 引用的 `use` 或 `include` 源。
- `/api/opencad/libraries` 返回的库文件。

当从另一个文件插入模块时，如果尚不存在，GUI 会添加一个 `use <file.scad>;` 引用。GUI 创建的模块调用会带有默认变换包装器发出：

```openscad
translate([0, 0, 0])
rotate([0, 0, 0])
scale([1, 1, 1])
module_name(param=value);
```

这使得后续的变换编辑具有确定性，并避免无休止地嵌套新的 `translate(...)` 或 `rotate(...)` 包装器。

## 选择模型

当前实现有意避免将任意渲染的网格三角形映射回源代码。相反，选择基于活动文件中显式的 `@cad:id` 锚定对象。

这比网格拾取更稳定，因为：

- WASM 输出可能会合并几何体并丢失源代码标识。
- 自定义模块可以产生许多内部网格。
- OpenSCAD 布尔运算可以移除或合并表面。
- 源代码回写需要可靠的代码范围。

目前，对象栏是规范的选择 UI。视口拾取可以稍后添加，但它应绑定到相同的 `@cad:id` 模型，而不是尝试从最终网格拓扑推断标识。

## 鼠标变换编辑

变换工具支持鼠标驱动的编辑：

- 平移编辑 `translate([x, y, z])`。
- 旋转编辑 `rotate([x, y, z])`。
- 缩放编辑 `scale([x, y, z])`。

轴向行为：

- 自由平移在当前视图平面内移动。
- X/Y/Z 平移使用轴向约束拖拽。
- 自由旋转使用指针移动调整旋转。
- X/Y/Z 旋转仅调整所选轴。
- 自由缩放是均匀的。
- X/Y/Z 缩放仅拉伸所选轴。

当变换包装器已存在时，GUI 修改该行。当不存在时，GUI 在锚定对象块内插入包装器。这防止了变换调用在编辑过程中被反复嵌套。

在鼠标拖拽期间，选定的对象在正式渲染模型上方显示为半透明的绿色交互层。正式模型保持可见，以便用户可以将新位置与装配体的其余部分进行比较。

## 交互预览渲染

有两条预览路径：

1. 简单图元通过 Three.js 在浏览器中直接解析和构建。
2. 自定义模块和浏览器解析器不支持的输出通过 OpenSCAD WASM 渲染为独立的交互预览。

交互预览使用独立的 Three.js 场景，叠加在正式场景之上。渲染器首先绘制正式模型，仅清除深度，然后绘制交互层。这避免了选定对象在与原始模型重叠时被深度测试隐藏。

自定义模块交互预览使用专用工作线程，因此不会取消或阻塞正常的完整场景渲染工作线程。临时预览代码使用单独的文件名：

```text
__openharness_interaction_preview.scad
```

如果选定的对象来自当前文件，临时代码会添加 `use <current-file.scad>;`。如果来自其他源，则添加 `use <source.scad>;`。

浏览器解析器可能会为被变换包装的不支持模块调用生成空组。因此，实现会检查浏览器构建的交互对象是否包含真实网格。如果不包含，则回退到 WASM 交互预览路径。

## 渲染控制

渲染行为当前为：

- 手动渲染：立即完整渲染。
- GUI 对象创建：插入代码并立即渲染。
- GUI 变换提交：更新源代码并渲染，同时保持相机。
- 自动渲染关闭：代码编辑仅将预览标记为过时。
- 自动渲染开启：代码编辑触发防抖的完整渲染并保持相机。

自动渲染设置使用 `localStorage` 持久化：

```text
openharness.opencad.auto_render
```

## 调试支持

预览包含一个可折叠的调试面板。默认情况下隐藏，并保留最新的 GUI 交互日志条目。它对于诊断对象选择和自定义模块预览行为很有用。

调试日志记录：

- 变换按钮点击。
- 选定对象 ID。
- 源代码块查找。
- 浏览器解析结果。
- 浏览器对象网格检测。
- WASM 回退开始。
- 工作线程进度、结果大小和错误。

面板可以展开、选择和复制，而不会触发 3D 视口拖拽事件。

## 当前已知限制

- 布尔编辑基于模板；尚无完整的多选布尔分组工作流。
- 模块参数编辑在插入时基于提示；尚无持久属性检查器。
- 视口点击选择尚不是规范的源代码选择；对象栏是可靠的选择机制。
- 复杂的 OpenSCAD 构造（如 `for`、`if`、`let`、`children()` 和表达式丰富的代码）会被保留，但无法通过 GUI 深度编辑。
- 浏览器回退预览对于布尔运算和不支持的构造是近似的。OpenSCAD WASM 仍然是权威渲染器。

## 开发计划

### 第一阶段：预览工具栏和锚定对象列表

状态：已实现。

- 在 3D 预览区域添加 GUI 工具栏。
- 按创建、工件/模块、操作、变换和轴向分组工具。
- 生成 `@cad:id` 锚点。
- 在预览对象栏中列出可选择的 GUI 对象。

### 第二阶段：图元和模块创建

状态：已实现。

- 插入立方体、圆柱体和球体模板。
- 从发现的符号插入模块调用。
- 添加缺失的 `use <...>` 引用。
- 为模块实例发出默认的平移/旋转/缩放包装器。
- 对象创建后立即渲染。

### 第三阶段：鼠标变换编辑

状态：已实现。

- 从对象栏选择锚定对象。
- 使用鼠标拖拽进行平移、旋转和缩放。
- 支持自由和轴向约束操作。
- 将更改回写到变换包装器。
- 提交渲染后保持相机。

### 第四阶段：自定义模块交互预览

状态：已实现。

- 检测不支持或无网格的浏览器预览输出。
- 通过 OpenSCAD WASM 渲染选定的模块块。
- 使用专用工作线程进行交互预览。
- 在正式场景上方显示半透明交互层。

### 第五阶段：渲染工作流控制

状态：已实现。

- 添加手动渲染。
- 添加持久的自动渲染切换开关。
- 代码编辑后防抖自动渲染。
- 保持 GUI 驱动的创建/变换渲染行为为即时。

### 第六阶段：属性检查器

状态：计划中。

- 为图元参数添加持久控件。
- 为模块调用参数添加持久控件。
- 支持数值、布尔值、字符串、向量和原始表达式值。
- 保留 GUI 无法评估的表达式。

### 第七阶段：布尔编辑工作流

状态：计划中。

- 支持从对象栏多选。
- 从选定对象生成并集、差集和交集块。
- 定义 `difference` 基础/减数对象的排序规则。
- 提供安全的取消分组/提取操作。

### 第八阶段：更丰富的选择和场景图

状态：计划中。

- 构建更完整的中间场景图，包含源代码范围。
- 在网格可以可靠地绑定到 `@cad:id` 的地方添加视口点击选择。
- 保留并显示不支持的/仅代码节点。
- 围绕源代码回写添加解析器/生成器测试。

## 实现文件

当前实现主要位于：

- `web_config/static/index.html`
- `web_config/static/css/app.css`
- `web_config/static/js/opencad.js`

每当 GUI 行为发生变化时，都应更新本文档，因为交互模型现在是 OpenCAD 编辑契约的一部分。
